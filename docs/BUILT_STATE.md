# RefreshDesk — Built State (audited from code 2026-10-05, commit 8910004; §2, §4, §5 refreshed and §8 added 2026-11-06 at the merge of Slice 7 into main; §1, §3, §6 and §7 updated 2026-10-14 and touched up on 2026-11-06)

## 1. Entity CDD flow
- **Entry:** `/dashboard/clients/[id]/entity-cdd` → `fetchEntityCddAction` (`app/dashboard/clients/[id]/entity-cdd/actions.ts`). Entity clients only. Roles: `read_only` cannot fetch; the app checks the role for the client's own firm (`getMembership`), and `save_entity_cdd` enforces it in the database (`require_role`, Slice 0b).
- **Input:** the browser posts only the client id and a company number, or the storage path of a PDF/JPEG/PNG (≤10 MB) that it has already uploaded straight to Storage under the user's own session (a Server Action body over 1 MB is refused, so files never go through the action; `parseFetchInput` rejects file bodies and fetched-data fields). The action checks the path is in this client's folder and that the bytes match the claimed type, registers a `client_documents` row (`document_type='incorporation'`), and sends it to Claude (the shared model constant in `lib/claude/model.ts`, prompt `v1.0-entity`) to extract the number. The number is then checked against `^([0-9]{8}|[A-Z]{2}[0-9]{6})$`.
- **kyc-search calls** (`lib/companies-house/kyc-search-client.ts`): `POST /auth/login` (admin email/password → `access_token`; a new login for every operation, nothing cached), then these run in parallel: `GET /companies/{n}`, `/companies/{n}/officers?fresh=true`, `/companies/{n}/pscs?fresh=true` (via `kycSearchGet`, which also reads `X-Fetched-At`). Filings use `GET /companies/{n}/filings` and `/companies/{n}/filings/{txId}/document` (PDF).
- **Stored:** RPC `save_entity_cdd` writes one `entity_cdd_records` row (`pending_review`) holding the raw profile, officers and PSCs, plus the computed chain and UBOs. It sets `fetched_by` from `auth.uid()` (Slice 0b).
- **Review gate:** `/entity-cdd/[recordId]/review` shows the profile, active officers, the PSC table, a ReactFlow org chart and Approve/Reject buttons. RPC `review_entity_cdd` locks the row, rejects records that are already reviewed, needs the `admin` role (admin is the reviewer; there is no reviewer role), and with `firms.four_eyes` on (the default) refuses an approval by the person who fetched the record (a null `fetched_by`, on old rows, is allowed and logged with a note; the fetcher may still reject). The review page disables the buttons with the reason shown. On approve it merges `company_number`, `registered_name`, `registered_address` and `incorporation_date` into `clients.details`, sets `last_refreshed_at`, recomputes `refresh_due_date` from `firm_refresh_rules`, and then embeds the client and the CDD record (Voyage). An embedding failure no longer surfaces as an error: it is logged and recorded as an `embedding.failed` audit event.
- **Audit events:** `entity_cdd.fetched` (payload includes the extraction model and prompt version), `entity_cdd.approved` / `entity_cdd.rejected` (with notes), `client.refreshed`, `document.uploaded`, `filing.saved`. The timeline UI has no labels for `entity_cdd.*` or `filing.saved`, so it shows the raw event type.

## 2. Ownership walker (`lib/ownership/walk.ts`)
- **Entry:** `walk(rootId, fetcher, policy)`, a breadth-first walk upwards. The root is a Companies House number or, if it matches `^[A-Z0-9]{20}$`, an LEI (a GLEIF walk). The fetcher is injected: no I/O, and no clock beyond `policy.now`, which the caller passes. Policy defaults: `maxDepth 6`, `threshold 25`, `indirectMethod 'either'`, `acceptRegulatedAsTerminal true`, plus the Slice 7 settings in §8.
- **Visited set:** keyed on `GB:<number>` or `LEI:<lei>`. Ceased PSCs are ignored.
- **Bands, not percentages:** natures are parsed into `[lo, hi]` bands and multiplied down the chain into `effectiveRange` (multiply, majority, or the larger of the two: `either`). A link held at more than 50%, or with a right to appoint directors, passes the full interest through. Control rights are never pruned.
- **Companies House outcomes:**
  - An individual PSC is `RESOLVED_INDIVIDUAL` (with `BAND_STRADDLES_THRESHOLD` if its range straddles the threshold, and the secondary flag `PSC_LOOK_THROUGH_LIKELY` when it probably sits above non-UK funds).
  - An open `psc-exempt-as-trading-on-uk-regulated-market` exemption is `RESOLVED_LISTED` (J Sainsbury plc, 00185647). An active statement with no PSCs is `PSC_STATEMENT`.
  - Other outcomes: `PSC_NONE_FILED`, `PSC_SUPER_SECURE`, `CIRCULAR_OWNERSHIP`, `DEPTH_LIMIT_REACHED`, `SOURCE_UNAVAILABLE`. A non-individual branch wholly below the threshold is `PRUNED` and not fetched.
- **Foreign owners (GLEIF):**
  - A corporate PSC with a non-UK registration is looked up in GLEIF by **registration number plus country only** (an ISSUED record, exactly one, normalised number): never by name. No unique match is a register stop with the country's reason code.
  - A GLEIF node follows its direct parent. That edge is accounting consolidation, not shareholding, so a walk with any GLEIF edge is capped at `partial`, and the nodes below a listed or regulated GLEIF parent get the secondary `CONSOLIDATION_ONLY`. GLEIF reporting exceptions map to `GLEIF_EXCEPTION_*` / `GLEIF_NO_KNOWN_PERSON`.
  - **Register profiles** (`lib/ownership/register-profiles.ts`): GB, IE, LU, NL, DE, FR, ES, DK, NO, SE, FI, US, KY, each with the register, whether basic data is free, whether shareholders and UBOs are public, the access routes, the document to request, and a stop reason. SE and FI are `verified: false`. Other countries (JE, GG, VG, CH, …) get `REGISTER_NOT_PROFILED`.
  - **Terminal checks** on GLEIF nodes (`terminals.ts`, `terminal-sources.ts`): an EU regulated-market listing (ESMA FIRDS, resolved to a venue and MIC through ESMA's regulated-market list, the operating MIC or ISO 10383) ends the walk as `RESOLVED_LISTED`; an authorised firm (ESMA register or ECB supervised list) ends it as `RESOLVED_REGULATED` when the policy accepts that. A US name match in the SEC ticker file is a secondary flag only (`LISTING_US_UNCONFIRMED`) and is skipped unless `SEC_USER_AGENT` is set (it is not). Every node records which checks ran and what each found (`checks`).
  - The profile's **Listing / regulation** row is built from the walk's terminal node (the root, else the shallowest listed or authorised ancestor) and lists the checks run, so it cannot contradict the Ownership row.
- **Client-provided evidence** (§8) may resolve a foreign register stop; the walk then ends `resolved_client_evidence` rather than `resolved`.
- **Overall status** (`WalkStatus`): `resolved` (no material UNRESOLVED leaf), `resolved_client_evidence` (the same, with at least one branch resolved on applied client evidence), `partial`, `unresolved`. Every `status === 'resolved'` check treats the new status as a pass but keeps its wording apart.
- **Production wiring (`lib/ownership/kyc-search-fetcher.ts`):**
  - The root's profile and PSCs come from `fetchEntityCdd`; each company above it uses `GET /companies/{n}` and `/pscs?fresh=true`; every company also calls `/exemptions`, and one with no active PSCs calls `/pscs/statements`. A CH 404 is "none on file"; a 429 becomes 503 with `Retry-After`, and a 5xx or network error is `SOURCE_UNAVAILABLE` (with `retryAfter` kept).
  - The fetcher also carries a GLEIF source (the shared rate-limited client) and the terminal checks. An optional `clientEvidence` loader is added by the ownership page when a walk is started from a client (§8).
- **Freshness:** each company node records `fetchedAt` (the oldest `X-Fetched-At` among its responses). Every register fetch of a run is in a source log, which a refresh pack stores.
- **Stored shape:** `toEntityCddOwnership` maps a walk onto the existing `ownership_chain`, `ubo_list`, `psc_data_quality` (`resolved_client_evidence` maps to `partial`) and `psc_warning`. The ownership page (`/dashboard/ownership`) does not save a walk; a refresh pack (Slice 6) does.

## 3. Data model (relevant)
- `clients`: `id, firm_id, client_type(individual|entity), display_name, risk_rating(low|standard|high), refresh_due_date, last_refreshed_at, status, details jsonb, external_ref`.
- `entity_cdd_records`: `id, firm_id, client_id, company_number, source_document_id→client_documents, company_profile/officers/pscs jsonb (raw), ownership_chain/ubo_list jsonb (OwnershipNode[]), psc_data_quality(full|partial|none), psc_warning, status(pending_review|approved|rejected), reviewed_by, reviewed_at, reviewer_notes, fetched_at, fetched_by (Slice 0b; null on older rows), created_at`. RLS allows SELECT for active firm members. All writes go through SECURITY DEFINER RPCs.
- **Ownership nodes:** there is no table. They are JSON `{name, kind, ownership_percentage, nature_of_control[], is_ubo, company_number?, address?}` stored inside the record. The extraction model and prompt version are kept only in `audit_events.payload`.
- `firms.four_eyes boolean default true` (Slice 0b): the maker cannot be the checker for entity CDD records, saved filings and refresh packs. `firm_members.role` is `admin | member | read_only`.
- `client_documents.status` also allows `pending` (Slice 0b): a saved Companies House filing waits there until an admin approves it; `uploaded_by` is who saved it.
- `refresh_packs` (Slice 6): `id, firm_id, subject, subject_name, policy jsonb, snapshot jsonb, snapshot_sha256, status(draft|submitted|approved|rejected), created_by, created_at, submitted_at, reviewed_by, reviewed_at, review_note`. A trigger refuses any change to the subject, policy, snapshot, fingerprint, firm, creator or creation time; rows are written only by RPCs (read for firm members, read_only included). Snapshots hold individuals as initials only and a check constraint rejects personal-data keys.
- `ownership_evidence`, `ownership_evidence_overview` (view), `firms.evidence_extraction_enabled`, and `client_documents.document_type = 'ownership_evidence'` (Slice 7; see §8).
- `extraction_embeddings.entity_cdd_id` (unique, vector(512)); `audit_events(firm_id, actor_user_id, event_type, entity_type, entity_id, payload)`.

## 4. UK / Companies House hardcoding
- **Still UK-specific:**
  - The company-number regex `^([0-9]{8}|[A-Z]{2}[0-9]{6})$` is in the entity CDD action and its Claude prompt (the form uses `maxLength=8`; `fetchEntityCdd` upper-cases). The walk's `UK_COMPANY_NUMBER` is the same pattern, used to decide whether a PSC or GLEIF registration is a UK company (an 8-digit number alone is not proof: Dutch KvK numbers look the same, so the register text is checked too).
  - CH field names: `natures_of_control` band strings, PSC `kind`, `name_elements`, `identification.registration_number`, `registered_office_address`, `date_of_creation`, `company_status`, `officer_role`, `resigned_on`, `notified_on`, `transaction_id`.
  - The UK regulated-market exemption id, the GLEIF registration authority for Companies House (`RA000585`), `GB:` node ids, "Companies House" copy and links, `en-GB` dates, and the UK rule cited in the listed-company note (MLR 2017 reg. 28(5)). `firms.country_code` defaults to `'GB'` (unused by the CDD flow).
- **No longer UK-only:** the ownership walk starts from an LEI, follows foreign owners through GLEIF, and stops at 13 profiled registers with country-specific reasons and documents to request (§2). The profile panel has a foreign variant built from GLEIF Level 1 data. Filings and officers have no free foreign source and are shown as "not available". Individuals are initials everywhere outside the evidence record.
- **Foreign-specific wording lives in data**, not code: `register-profiles.ts` (documents to request, notes, `lastVerified`) and `reason-text.ts` (the next step for each reason; every register-stop reason now leads with "request written confirmation of ownership from the client").

## 5. External dependencies, rate limits, costs
- **kyc-search** (separate Python/FastAPI service; `KYC_SEARCH_URL`, `KYC_SEARCH_ADMIN_EMAIL/PASSWORD`). A fetch makes 4 calls; every view of a client detail page with an approved CDD makes 2 (login + filings); a walk makes 2 calls per company plus exemptions and statements; saving N filings makes 2 + 2N. CH rate limits and hosting cost are UNVERIFIED. No timeout, retry or rate limiting on these calls.
- **GLEIF API** (public, CC0): one shared client with a 50-requests-a-minute limiter and a 24-hour cache (30 days for legal-form and registration-authority names), in-process only.
- **ESMA** registers (Solr cores for FIRDS instruments, the regulated-market list and authorised firms; 250 ms minimum gap, cached for a day), the **ISO 10383** MIC list (weekly), the **ECB** supervised-entities workbook (weekly). **SEC** ticker file: needs `SEC_USER_AGENT`, which is not set, so it is skipped.
- **Anthropic:** every extractor uses one model constant, `CLAUDE_MODEL` in `lib/claude/model.ts` (default `claude-sonnet-5-5`, overridable with `ANTHROPIC_MODEL`). The previous id, `claude-sonnet-4-20250514`, now returns 404, which had silently broken all extraction until 2026-10-16. Calls: uploaded document extraction (`max_tokens` 2048), incorporation-document company number (1024), client ownership evidence (4096, prompt `ownership-evidence-v1`, only if the firm switched it on). Cost is not tracked.
- **Voyage `voyage-3-lite`:** one or two embeds per approval, skipped when the content hash is unchanged.
- **Supabase** (Postgres, Storage bucket `kyc-documents`, pgvector, RLS). The remote project and `supabase migration list --linked` agree with the local migrations through `20261018000000`.
- **Environment variables** (names only). In `.env.example`: `ANTHROPIC_API_KEY`, `KYC_SEARCH_URL`, `PACK_SIGNING_SECRET` (16+ characters; without it the pack Save button is disabled), the Supabase and Stripe keys. Also read, not in `.env.example`: `KYC_SEARCH_ADMIN_EMAIL`, `KYC_SEARCH_ADMIN_PASSWORD`, `VOYAGE_API_KEY`, `RESEND_API_KEY`, `CRON_SECRET`, `APP_URL`, `SUPABASE_DB_PASSWORD`. Optional: `ANTHROPIC_MODEL`, `SEC_USER_AGENT`, `DEMO_SUBJECT_FIRM_SLUGS`.

## 7. Changes since the audit (2026-10-14)

### Slice 0b: permissions in the database
- Migration `20261014000000_slice0b_permissions.sql`, **applied to the live database**.
- `public.require_role(firm_id, roles[])` is called at the top of every write RPC that previously checked only active membership: create_client, import_clients, register_document, save_extraction, save_entity_cdd, the three `upsert_*_embedding` RPCs (admin or member), and review_entity_cdd, review_extraction, approve_filing_document (admin only). `read_only` can no longer write. Admin is the reviewer; there is no reviewer role.
- `is_admin_or_analyst_of_firm` was repaired (it still looked for the `analyst` role that the multi-user migration (20260607010000) had removed), so admins and members can update and archive clients again.
- **Filings are maker-checker.** Saving a filing (member or admin) registers it with status `pending`; an admin approves it, and with `firms.four_eyes` on, not the person who saved it. Pending filings show "Pending approval" and admins get an Approve button. Filings saved before this that were never approved were moved to `pending`.
- Dry-run tooling: `scripts/run-dryrun.cjs` runs migrations and SQL tests over one connection inside a transaction that is always rolled back (see `supabase/README.md`).

### Uploads no longer pass through Server Actions
- A file over 1 MB posted through a Server Action fails with "Body exceeded 1 MB limit", although the forms promised 10 MB. The entity CDD fetch form and the Documents upload form now upload to Storage from the browser and send only the path. `bodySizeLimit` is unchanged. The server checks the path is in the client's folder and the bytes match the claimed type.

### Slice 6: refresh packs
- Migration `20261015000000_slice6_refresh_packs.sql`, **applied to the live database** (dry run: 64 checks passed).
- A refresh pack is a saved, unchangeable record of an ownership run: the snapshot is exactly what the pack page renders (KYC profile rows, ownership nodes and edges with resolutions, reason codes and ranges, points to check, summary with open-branch count, and a **source log** of every register fetch: register, endpoint path, fetched-at, status, cached or not), with a SHA-256 fingerprint over canonical JSON (sorted keys, no whitespace). Individuals are initials only; the builder refuses to build if a known name leaks.
- RPCs: `create_refresh_pack` (member or admin), `submit_refresh_pack` (creator), `approve_refresh_pack` / `reject_refresh_pack` (admin; with four-eyes the creator cannot approve; reviewed once; rejecting needs a note). Audit events `refresh_pack.created|submitted|approved|rejected`.
- UI: "Save as refresh pack" on `/dashboard/ownership`; `/dashboard/packs` (list); `/dashboard/packs/[id]` renders only from the snapshot (static SVG chart, source log, sign-off) and recomputes the fingerprint ("Fingerprint verified" or a red mismatch warning); "Download PDF" is the browser print dialog with a print stylesheet (fingerprint repeated in every page footer).
- The server signs each snapshot (HMAC, `PACK_SIGNING_SECRET`, 16+ characters, bound to the firm and valid for an hour) so only a snapshot it built can be saved. **Without that environment variable the Save button is disabled.** A user in several firms gets their earliest firm (the app has no "current firm" yet).
- Not enforced in the database: that the stored fingerprint equals the hash of the snapshot (canonical JSON is computed in TypeScript; the pack page verifies it). Deleting a firm cascades to its packs.

## 8. Slice 7: client-provided ownership evidence (merged 2026-11-06)
Design: `docs/slice7-client-evidence.md`. Browser test: `docs/slice7-test-walkthrough.md`. Migrations (all applied to the live database): `20261016000000_slice7a_client_evidence.sql` (table, RPCs, validation, extraction setting), `20261017000000_slice7e_evidence_followup.sql` (a draft can be withdrawn without a proposal; the "already open" message), `20261018000000_slice7f_confirmation_kind.sql` (the confirmation kind, `certified = 'not_applicable'`). Slices 7b to 7d are application code only. A digital-signature check (Slice 8) is specified in `docs/slice8-esignature-verification.md`, not built.

**What it is.** Where the registers cannot show who owns a foreign company, a member uploads what the client provided, an admin other than the uploader confirms it, and only then can the walk use it.

- **States** (`ownership_evidence.status`): `draft` (uploaded, no owners yet) → `proposed` → `confirmed`, or `rejected` (from draft or proposed; a rejected draft has no proposal); a newer confirmation for the node makes the old one `superseded`. **Nothing is ever deleted** (a trigger refuses every DELETE; a confirmed row can only become superseded; rejected and superseded rows are frozen). One open item (draft or proposed) and one confirmed item per node.
- **Node key rule.** A node is identified by an exact LEI or a registration number with its two-letter country, never a name: key `LEI:<lei>`, else `REG:<CC>:<number upper-cased with spaces, dots, hyphens and slashes removed>`. Evidence is filed against the walk's root (`subject_id`, upper-cased) and the client. The walk matches a node on an exact LEI, or on an exact registration number (normalised) plus country; the newest confirmed item wins. Company owners the evidence names are followed only on a printed number and country (or LEI) that point at one record; a name is never searched.
- **Kinds** (`evidence_kind`): `client_ownership_confirmation` (primary and the form's default: a signed letter, email or signed chart from the client), `shareholder_register`, `register_extract`, `annual_report_page`, and the older `signed_structure_chart` (accepted, no longer offered, treated as a confirmation).
- **Certification and capacity fields** (names are never kept, only capacities):
  - A confirmation has **no certification**: `certified = 'not_applicable'` (enforced by a database constraint that pairs the two confirmation kinds with it and every other kind with yes, no or unclear). It carries `confirmed_by_capacity` (director, company_secretary, authorised_signatory, compliance_officer, other, unclear), `confirmation_date`, `received_as` (signed_letter, email, signed_chart, other).
  - Other kinds carry `certified` (yes, no, unclear), `certifier_capacity` (notary, lawyer, accountant, company_officer, other, unclear) and `certification_date`. The certifier's own text is stored on the evidence row only.
  - Every owner has the name as shown (stored on the row; admins and members only), initials set by the server, a holding (percent or band, as printed), an optional registration number and country or LEI, and a required page reference. The database refuses date-of-birth, nationality, residence and occupation keys.
- **Coverage rule.** The listed holders' lower bounds are summed (a holding not printed counts as 0). If 100 minus that is at or above the threshold, an unlisted holder could be a beneficial owner and the evidence does not resolve the node. A document must say it lists every holder, **or** state that "no other person holds X% or more" with X at or below the threshold, which completes coverage like a full list. Nothing overrides coverage.
- **Policy** (on the ownership page when it is opened from a client, recorded in a pack's policy): `acceptClientEvidenceAsResolved` (default true; off, evidence is shown but the branch stays partial), `maxEvidenceAgeMonths` (12; age from as-at, else the confirmation or document date), `acceptEmailConfirmation` (true; off, an emailed confirmation stays partial). Blockers: stale, uncertified (never for a confirmation), incomplete, email. An admin can confirm with an override for `stale` (valid for the age limit after confirmation) or `uncertified` (not for a confirmation; never waives age), with a mandatory note.
- **Resolution status.** Evidence is applied only at a foreign stop whose reason is a register stop or a GLEIF exception (never over a listing, a Companies House finding, a loop, a depth limit or an outage). The node becomes `PENDING` with owner nodes (initials only, edges `source 'client'`); the walk ends `resolved_client_evidence`, shown as "Complete — N branches resolved on client evidence". Reason codes `CLIENT_EVIDENCE_INCOMPLETE | STALE | UNCERTIFIED | EMAIL_NOT_ACCEPTED` (primary on a node whose evidence could not be used), `CLIENT_EVIDENCE_APPLIED | NOT_ACCEPTED | PENDING` (secondary). Owners reached over a GLEIF consolidation link get no effective range, so those walks stay partial.
- **Extraction toggle.** `firms.evidence_extraction_enabled` defaults to **false**; an admin switches it on in Settings (`set_evidence_extraction`, audited as `firm.evidence_extraction_changed`). The 7a migration turned it on for the slug `refreshdesk-sql-test-1778359800` only; the demo firm `bubble-up` was switched on in Settings. With it off, or if Claude fails, the uploader types the owners in. A failed read shows its reason on the item page and is logged (code, status, request id, never the document). Claude is only a reader: it is never asked to look anything up.
- **Database and RPCs** (all `security definer`, via `require_role`): `create_ownership_evidence` (member or admin), `save_evidence_proposal` (the uploader), `confirm_ownership_evidence` (admin; with `firms.four_eyes` on, not the uploader), `reject_ownership_evidence` (admin, or the uploader withdrawing; a note is required), `set_evidence_extraction` (admin), `confirmed_evidence_for` (any member; read_only gets no names). The table is readable by admins and members; read_only reads `ownership_evidence_overview`, which has no names or payloads. Audit events `ownership_evidence.created | proposed | confirmed | rejected | superseded` hold ids, kinds, counts and hashes, never names. A document of type `ownership_evidence` can only be registered through `create_ownership_evidence`.
- **Pages.** `/dashboard/clients/[id]/evidence/new` (browser-to-Storage upload; only the path reaches the action), `/dashboard/clients/[id]/evidence/[evidenceId]` (document beside an editable owners table, live coverage, GLEIF display lookup on printed numbers, four-eyes gate shown before the click, confirm, reject or withdraw), `/dashboard/evidence` (the queue), a Settings toggle, and from a client page `/dashboard/ownership?client=<id>` with an "Add client evidence" button at the top of an unresolved foreign node's panel.
- **Refresh packs.** A pack's snapshot gets a `clientEvidence` block per node that met evidence (kind, dates, certified or the confirmation capacity, date and channel, the confirming admin's user id, the document's SHA-256, `overrideExists`, why it was not used) and one source-log line per item. Never the certifier's or signatory's name, an override's note or an owner's name. Saving a pack re-checks that the evidence is still confirmed and unchanged.
- **DEMO-FJORDVIK.** A built-in sample subject for the full flow, with no network calls: a fictional UK company (`SAMPLE DATA: Fjordvik Demo (UK) Limited`) whose only owner is the fictional Fjordvik Test Holding AS (NO, 999 000 001), so the walk stops there as an unresolved foreign node. Offered only to firms whose slug is in `DEMO_SUBJECT_FIRM_SLUGS` (default `bubble-up`). It is labelled "Sample data" in the viewer, every profile row, the evidence pages and queue, and any pack built from it (a `sample` flag in the snapshot, the subject name and a banner). Fixtures: `__fixtures__/evidence/SAMPLE-ownership-confirmation.pdf` (a fictional director's signed letter) and `SAMPLE-shareholder-register.pdf`, made by `scripts/make-sample-register.cjs`.
